# 중간 지점 추천 서비스 — 설계 문서

- 작성일: 2026-07-31
- 상태: 사용자 검토 대기

## 1. 문제 정의

서로 다른 지역에서 출발하는 친구들이 약속을 잡을 때 두 가지가 반복적으로 어렵다.

1. 어디서 만나야 다들 이동 부담이 비슷한지 알기 어렵다.
2. 만나는 목적(저녁·카페·영화·전시 등)에 맞는 장소를 그 지점 주변에서 고르기 어렵고, 도착했더니 문이 닫혀 있는 경우가 있다.

이 서비스는 참가자들의 출발지·출발시간·만남 목적을 입력받아 ① 이동시간이 가장 공평한 지점을 추천하고, ② 그 지점에서 선택한 목적에 맞는 장소를 도착 예상 시각·영업시간을 고려해 추천하고, ③ 여러 목적을 골랐다면 순서까지 짠 코스 일정을 만들어준다.

## 2. 목표 / 비목표

**목표 (MVP)**
- 2~4인 참가자의 출발지·출발시간·목적 카테고리(복수 선택) 입력
- 대중교통 이동시간 균등도 기준 중간 지점 추천 (환승 횟수는 동점 시 보조 기준)
- 선택 카테고리가 풍부한 지점을 우선하는 랭킹
- 카테고리별 표준 영업시간 규칙 기반 "마감 임박/마감" 배지
- 중간 지점에 조건에 맞는 곳이 없을 때, 어느 참가자 쪽에 가까운지 밝히는 폴백 추천
- 여러 카테고리 선택 시 도착 시각부터 자동으로 코스 시간표 구성 + 드래그로 순서 수정
- 로그인·DB 없는 상태 비저장(stateless) 서비스

**비목표 (이번 범위 밖)**
- 로그인/회원, 약속 히스토리 저장
- 참가자별 개별 입력(링크 공유형 방 만들기) — Q2에서 A안(한 사람이 일괄 입력)으로 확정
- 5인 이상 개별 입력 지원 — 대표 출발지 입력으로 안내만 하고 시스템적으로 막지는 않음
- 참가자 간 장소 투표/채팅
- 실시간 정확한 영업시간 조회 (카카오·네이버 API가 제공하지 않음)
- 한국 외 지역 지원 (ODsay가 국내 전용)

## 3. 사용자 흐름

```
1. 참가자 입력    참가자별 출발역 + 출발시간, 만남 목적 카테고리(복수) 선택
2. 계산 중        이동시간 균등도 기준으로 후보 역 랭킹 계산
3. 추천 결과      1위 지점 + 공정성 지표(이동시간 차이, 참가자별 소요시간) + 대안 목록
4. 장소 탐색      선택 지점 기준 카테고리별 장소, 마감 임박 배지, 부족하면 폴백 카드
5. 코스 스케줄    선택한 카테고리들을 자동 정렬한 시간표, 드래그로 순서 변경 가능
6. 장소 상세      Bottom Sheet로 사진/배지/설명 + 카카오맵 원문 링크
```

와이어프레임(6개 화면, LDS 컴포넌트 기반)은 아티팩트로 승인 완료: `design-system/wireframes.html`

## 4. 핵심 알고리즘

### 4.1 중간 지점 랭킹

1. 후보 역 풀은 전국 주요 환승·번화가 역 30~50곳으로 미리 큐레이션한 고정 목록을 사용한다 (예: 강남·홍대입구·신도림·서면·동대구 등 노선 교차가 많거나 상권이 큰 역). 매 검색마다 전국 모든 역을 탐색하지 않음으로써 ODsay 호출량도 예측 가능해진다.
2. 각 참가자 출발역 → 후보 역 각각까지의 대중교통 소요시간·환승횟수를 ODsay로 조회한다.
3. 후보 역마다 "이동시간 차이"를 `max(소요시간) - min(소요시간)`으로 계산한다. 이 값이 작을수록 순위가 높다. **이것이 항상 1순위 기준이다.**
4. 이동시간 차이가 동일한 후보가 여러 개면, 총 환승 횟수 합이 적은 쪽을 우선한다.
5. 선택한 카테고리 각각에 대해 해당 역 주변 장소 수(밀집도)를 카카오 로컬 API로 조회하고, 카테고리 전부가 최소 기준 개수(카테고리당 3곳) 이상인 역만 최종 후보로 남긴다.
6. 최종 후보가 없으면 §4.2 폴백으로 넘어간다.

**가정 [확인 필요]**: 큐레이션 역 목록의 구체적인 구성(어느 지역까지 포함할지)과 카테고리당 최소 3곳 기준은 초안이며, 사용자 확인 후 조정한다.

### 4.2 폴백 추천

1. 최상위 후보 역에서 카테고리 기준(3곳 이상)을 만족하는 곳이 없으면, 공정성 순위를 유지한 채 그다음 순위 후보 역들로 기준을 재적용한다.
2. 그래도 없으면 카테고리 최소 기준을 낮추거나(예: 3곳 → 1곳), 후보 역 풀 밖이라도 특정 참가자 출발역에 가까운 장소를 추천한다. 이때 "OO님 쪽에 가까운 곳이에요"처럼 누구에게 유리한지 결과 문구에 명시한다. (와이어프레임 프레임 4 참고)

### 4.3 영업시간 근사 규칙

카카오·네이버 장소 API는 영업시간을 제공하지 않으므로, 카테고리별 표준 영업시간 규칙으로 근사한다.

| 카테고리 | 가정 마감 시각 |
|---|---|
| 식사 | 22:00 |
| 카페 | 22:00 |
| 술 | 24:00 |
| 영화 | 필터 미적용 (심야 상영 존재) |
| 전시 | 18:00 |
| 쇼핑 | 21:00 |
| 액티비티 | 23:00 |

- 도착 예상 시각이 마감 2시간 이내면 "마감 임박" 배지(caution)를 표시한다.
- 마감 이후로 계산되면 기본 목록에서 제외한다.
- 모든 장소 카드/상세 화면에 "정확한 영업시간은 카카오맵에서 확인하세요" 안내와 카카오맵 링크를 함께 둔다.

**가정 [확인 필요]**: 위 시각과 "2시간 임박" 기준은 초안이며, 실제 서비스 운영 데이터 없이 정한 값이라 조정 여지가 크다.

### 4.4 코스 자동 정렬

- 선택한 카테고리를 상식적 순서(식사 → 카페 → 영화/술) + 각 장소의 가정 마감 시각을 고려해 배치한다. 마감이 이른 카테고리(전시)를 앞으로 당긴다.
- 사용자가 드래그로 순서를 바꾸면 도착 시각부터 순차적으로 시간표를 재계산한다.

## 5. 참가자 입력 규칙

- 2~4명 지원.
- 5명 이상을 시도하면 차단하지 않되 "비슷한 지역끼리 묶어 대표 출발지 하나로 입력해보세요" 안내 문구를 노출한다. (인원이 늘수록 중간 지점이 연고 없는 곳으로 수렴하는 것을 막기 위함)
- 출발역 입력은 검색형 Input(카카오 로컬 API 자동완성)으로 받는다.

## 6. 기술 스택 & 아키텍처

- **프레임워크**: Next.js (App Router) — 화면과 API 프록시를 한 프로젝트에서 관리
- **배포**: Vercel
- **지도**: 카카오맵 JS SDK — 장소 검색을 카카오 로컬 API로 하므로 좌표계·장소 ID를 그대로 이어 쓰기 위해 지도도 카카오로 통일
- **대중교통 경로**: ODsay API — 전국 대중교통 소요시간·환승횟수를 제공하는 사실상 유일한 국내 API (네이버/카카오는 자동차 길찾기만 공개 제공)
- **장소 검색**: 카카오 로컬 API 우선, 네이버 지역검색 API를 보완용으로 병행 (카카오에 없는 장소 보강)
- **API 프록시**: Next.js Route Handler. ODsay·카카오·네이버 REST 키는 서버 환경변수로만 보관하고 브라우저에 노출하지 않는다. 네이버 지역검색 API는 CORS 미지원이라 프록시가 필수다.
- **저장소**: 없음. 로그인·DB 없이 요청-응답으로만 동작하는 상태 비저장 구조.

### API 호출량 참고

- ODsay 무료 티어: 하루 1,000회
- 한 번의 검색: 후보 역 약 20개 × 참가자 최대 4명 = 최대 80회 → 하루 약 12회 검색 가능한 여유
- 자주 반복되는 (출발역 → 후보역) 조합은 프론트 세션 캐시로 재조회를 줄일 수 있음 (MVP 필수 아님, 여유 있으면 추가)

## 7. 디자인 시스템

LINE Design System(LDSM) 공개 문서를 분석해 토큰·컴포넌트를 구축했다.

- `design-system/tokens.css` — 색상(라이트/다크 시맨틱 매핑 포함), 타이포 스케일, 레이아웃(16pt 마진, 2/3/4컬럼 그리드), 셰이프/엘리베이션
- `design-system/components.css` — Top Navigation, Box/Capsule Button, Chips, Input, List, Card, Badge, Bottom Sheet, Snackbar, Progress 등 LDS 컴포넌트 + 서비스 전용 컴포넌트(공정성 미터, 코스 타임라인, 지도 플레이스홀더)
- `design-system/wireframes.html` — 위 컴포넌트로 조립한 6개 화면 와이어프레임 (아티팩트로 확인 완료)

LDS 그린(#06C755)은 LINE 상표이므로, 실제 커머셜 배포 시 `--color-brand` 계열 토큰 3개만 교체하면 브랜드를 바꿀 수 있도록 시맨틱 레이어로 분리해뒀다.

## 8. 에러 처리

- 출발역 검색 결과 없음 → Input 헬퍼 텍스트에 안내
- 특정 참가자-후보역 간 대중교통 경로를 ODsay가 찾지 못함 → 해당 후보를 랭킹에서 조용히 제외
- 선택한 모든 카테고리가 모든 후보 역에서 기준 미달 → §4.2 폴백 흐름
- 카카오/네이버/ODsay API 장애 → 해당 소스만 건너뛰고 나머지로 결과를 구성, 화면에 "일부 정보를 불러오지 못했어요" 정도로만 표시 (구체 문구는 구현 단계에서 확정)
